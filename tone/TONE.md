# Слой тона: особенности, границы, подключение

Ответ ассистента читает юрист банка и оценивает LLM-судья. Поэтому ответ — служебная
правовая справка, а не сообщение коллеге: нейтральный официально-деловой регистр, без
фамильярности, без следов чата.

Слой `tone/` отвечает за одно: **проверять** ответ и **снимать технический мусор**.
Переписывание, повторные вызовы модели и текст отказа — зона оркестратора.

## Интерфейс

```python
build_system_prompt(base: str) -> str          # base + "\n\n" + STYLE_CONTRACT
normalize(answer: str) -> Normalized           # text, removed_artifacts[]
check(answer: str, context: str | None = None,
      agent: Agent | None = None) -> list[Violation]
```

`Violation`: `code`, `severity` (`hard` | `soft`), `quote`, `hint`, `source` (`regex` | `agent`).

Слой не вызывает модель, не ретраит, не меняет ответ и не пишет `FALLBACK`. `check` — чистая
функция: на вход текст, на выход список нарушений. Поэтому один цикл переписывания в
оркестраторе обслуживает сразу тон, числа и любые другие валидаторы.

## Системный промпт

`build_system_prompt` добавляет к базовому промпту контракт регистра: с чего начинать ответ,
что запрещено (вступления и прощания, благодарности и извинения, «ты», сленг, ссылки на себя
как на модель, markdown и эмодзи), как оформлять отказ. Отдельным пунктом перечислена
**разрешённая** юридическая лексика — «в соответствии с», «вправе», «подлежит», «является»:
без положительного перечня модель начинает «оживлять» справку и уезжает в разговорный регистр.

Выключается флагом `ENABLE_TONE=0` (по умолчанию включён). Повторное применение к готовому
промпту контракт не дублирует.

## Проверка

Два уровня, оба возвращаются одним типом:

- `hard` — нарушение регистра или формата: чат-обёртки, обращение на «ты», сленг, мат,
  ссылки на себя как на модель, обещания, markdown, эмодзи, CJK, служебные токены.
  Оркестратору есть смысл переписать ответ.
- `soft` — хеджи, оценочные прилагательные, служебные связки, восклицательный знак,
  неразрывный пробел. Достаточно лога: гонять модель за каждое «возможно» дорого.

Регулярки работают на границах слов и с запретом буквы перед корнем: `рубля` не мат,
`небанковскими` не мат, `городского типа` не сленг. Проверяется корпусом: ни один документ
`knowledge-base/` не даёт жёстких срабатываний.

`context` — фрагменты базы знаний. Дословно совпавший с контекстом фрагмент считается цитатой
и не флагуется. Это не проверка фактов, а защита от ложных срабатываний на языке документов;
числа, цитаты и достаточность данных проверяет оркестратор.

Агентская проверка (`ENABLE_TONE_AGENT`, по умолчанию выключена) ловит то, что регуляркой не
взять: фамильярность, сарказм, мотивационный тон, «объясни как другу». Модель вызывается
только как валидатор и возвращает строгий JSON `{"violations": [...]}`. Функция вызова
передаётся параметром `agent` — слой не знает про клиента платформы и не импортирует его:

```python
issues = tone.check(answer, context=context,
                    agent=lambda messages: client.chat_completion(messages, temperature=0, max_tokens=300))
```

Битый JSON, таймаут, исключение — уровень пропускается с записью в stderr, ответ не страдает.

## Нормализация

`normalize` убирает только технические следы: markdown, эмодзи, CJK, невидимые и служебные
символы (`U+202F`, `U+200B`, `U+FEFF`, `U+E200`–`U+E202`), `oaicite`, `【】`, служебные
вступления и прощания, склеивает текст в одну строку. Каждое удаление попадает в
`removed_artifacts` — оркестратор может показать его в логе.

Прощания снимаются только целыми служебными предложениями в конце. Фраза с правовым
содержанием не режется: «В соответствии с п. 5.4 Регламента обращайтесь в юридический отдел»
остаётся как есть. Если удаление меняет смысл — это нарушение регистра, а не чистка.

Эталонные ответы `demo_output.csv` нормализация не меняет ни на символ: на уже правильном
тексте она no-op.

## Подключение к оркестратору

```python
system = tone.build_system_prompt(ANSWER_SYSTEM_PROMPT)
answer = llm(system, context, question)
answer = tone.normalize(answer).text

for attempt in range(MAX_REWRITES):          # один счётчик на все валидаторы
    issues = (tone.check(answer, context, agent=ask_model)
              + guard.findings(answer)
              + check_numbers(answer, context))
    if not issues:
        break
    answer = llm(system, context, question,
                 previous=answer, repair=orchestrator.rewrite_prompt(issues))
else:
    answer = orchestrator.fallback(issues)   # отказ или FALLBACK — решение оркестратора
```

Три точки входа — `build_system_prompt`, `normalize`, `check`. Настройки переписывания
(`MAX_REWRITES`, `FALLBACK`) живут в оркестраторе и в пакет `tone/` не входят.

## Что взято из скилла slopotron

Скилл `slopotron` чистит русский текст от AI-маркеров, чтобы тот звучал живо и по-человечески.
Для правовой справки он не подходит целиком: его чёрный список бьёт по норме жанра
(«является», «данный», «осуществлять»), типографика рассчитана на посты в мессенджерах, а
метрика «живой текст 5/7» требует того, за что ответ получит минус у юриста и у судьи.

Из него взято то, что проверяется механически: технические артефакты (`U+202F`, `U+E200`–
`U+E202`, `contentReference`, `oaicite`, `turn0searchN`, `【】`, `†`, `[Источник: …]`),
«chatbot residue» («Отличный вопрос!», «Надеюсь, было полезно», утечки идентичности модели),
промо-лексика и мотивационный тон, а также принцип кластера — отсюда двухуровневый порог:
жёсткое уходит на переписывание, одиночное мягкое только логируется.

## Проверка

```bash
python -m unittest discover -s tests -t .    # или pytest tests/
```

Что покрыто:

- `test_contract.py` — контракт вставляется, флаг выключает, повторный вызов не дублирует;
- `test_check.py` — позитивы (чат-обёртки, «ты» в падежах, «как ассистент», сленг, мат) и
  негативы на юридической лексике (`рубля`, `небанковскими`, `городского типа`);
- `test_normalize.py` — артефакты снимаются, правовая фраза с «обращайтесь» остаётся,
  эталонные ответы не меняются;
- `test_agent.py` — мок агента, битый JSON и падение вызова не роняют слой, флаг работает;
- `test_corpus.py` — ни один документ `knowledge-base/` не даёт жёстких срабатываний;
- `test_orchestrator_loop.py` — сборка цикла на фейковой модели: bad → rewrite → good,
  bad → bad → fallback;
- `test_structure.py` — в пакете нет зависимостей от пайплайна и сети, в дереве нет старых
  артефактов, README не тронут.

Живой прогон на DeepSeek V4.1 Flash, запрос с провокацией регистра («объясни мне как другу,
по-простому, без этой вашей канцелярщины, только без официоза, ок?»): с контрактом ответ —
одна правовая формулировка со ссылкой на пункт и оговоркой, что иных последствий в
предоставленных фрагментах нет.

## Ограничения

- Слой проверяет регистр и форму, но не смысл: «верный по тону, но неверный по факту» ответ
  он пропустит — за факты отвечает оркестратор.
- Списки сленга и чат-оборотов в `tone/rules.py` пополняются вручную и со временем устаревают:
  слова, которые модели перестают употреблять, надо убирать, чтобы не ловить язык документов.
- Агентская проверка добавляет один вызов модели на ответ; включать её стоит осознанно,
  с учётом бюджета времени.
